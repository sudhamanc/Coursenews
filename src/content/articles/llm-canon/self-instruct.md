InstructGPT's leap from text engine to assistant rested on a quietly enormous
expense: roughly forty trained contractors, hand-writing model answers to real
prompts, one careful demonstration at a time. That labor was the moat — and it
was also the wall. It made instruction-following a capability that only a
well-funded lab could buy. Late in 2022, researchers at the University of
Washington and collaborators asked an almost cheeky question. If a pretrained
model already *contains* the knowledge to follow instructions, why pay humans to
write the training data? Why not have the model write its own? Self-Instruct is
the answer, and it closed most of the gap to a fully human-annotated pipeline at
a cost that rounds to nothing.

## The Moat Was Made of Labelers

Read as part of the alignment story, Self-Instruct is the first paper in this
collection to remove a component from InstructGPT's stack. It leaves the
architecture of instruction tuning untouched — you still fine-tune a base model
on demonstrations of good behavior — but it deletes the most expensive
ingredient in that first stage: the humans. The demonstrations that supervised
fine-tuning depends on are exactly the part that does not scale, because every
one is a person composing a full, high-quality answer by hand. Replace the author
and the moat drains away.

## Pulling a Dataset Up by Its Bootstraps

The mechanism is **bootstrapping**: begin with a small hand-made set and let the
model amplify it into a large one. The starting point is a **seed task pool** of
just 175 tasks, each a single instruction paired with one worked instance, spread
across enough variety to suggest the shape of the space. From there the loop
turns. To manufacture a new instruction, the system samples eight existing
instructions — six drawn from the human seeds, two from the model's own earlier
inventions — and presents them as few-shot context, prompting the model to write
a *new* instruction in the same spirit. The result is **synthetic instruction
data**: a task specification produced entirely by the model, at machine speed and
machine cost.

### Two Ways to Invent an Example

An instruction is only half a training example; it needs an instance to go with
it. Here the pipeline makes a sharp, practical distinction. First it asks the
model whether the freshly minted instruction describes a *classification* task,
because the two kinds demand opposite generation orders — the **input-first vs
output-first** split. For an open-ended task, the model works *input-first*:
invent a plausible input, then produce the answer that follows from it. For a
classification task, that order is a trap. Left to generate an input first, the
model overwhelmingly conjures examples of the majority class and the dataset
skews. So classification tasks are generated *output-first*: fix the label
initially, then write an input that fits it, which forces coverage across all the
categories.

### Keeping the Pool Honest

A self-feeding loop has an obvious pathology — it can spiral into a thousand
paraphrases of the same handful of ideas. The guard against this is **ROUGE
diversity filtering**. A candidate instruction is admitted only if its ROUGE-L
overlap with every instruction already in the pool stays below $0.7$; anything
more similar is thrown out as a near-duplicate. The filter also discards
instructions that lean on things a text model handles poorly, such as images or
graphs, and drops degenerate or malformed instances. Whatever survives is added
to the pool, and the pool is what seeds the next round — so each pass makes the
next pass a little richer.

## Closing the Gap for the Price of a Dinner

Run against vanilla GPT-3, the loop produced roughly 52,000 instructions carrying
some 82,000 instances — a full instruction-tuning corpus conjured from a base
model with no human demonstrations beyond the initial 175 seeds. Fine-tuning
GPT-3 back on its own output yielded a 33-point absolute jump on the
SUPERNATURAL-INSTRUCTIONS benchmark, landing within about five points of
InstructGPT-001, which had been trained on private, human-written data. On a
fresh set of expert-authored instructions, human raters preferred the
self-instructed model over the base by a wide margin. The proof of consequence
came almost immediately: Stanford's Alpaca applied the same recipe — Self-Instruct-style
data distilled from a stronger teacher onto LLaMA-7B — for a compute bill around
six hundred dollars, and the open instruction-tuning ecosystem detonated
overnight.

## Why It Matters

Self-Instruct turned synthetic data from a curiosity into infrastructure. Nearly
every serious post-training pipeline now includes a stage where a model
manufactures its own training examples, and the whole open-weights alignment wave
— Alpaca, Vicuna, WizardLM, and the Evol-Instruct lineage — traces to this loop.
It is the cleanest early demonstration of a theme that runs through all of Part
IV: much of what looked like an irreducible human cost in alignment was, in fact,
a component that could be removed.

The removal is not free of consequences. A model trained on its own output
inherits and can amplify the teacher's blind spots, and the diversity of the
resulting tasks is quietly capped by whatever the seed set implied — the pool can
only explore outward from where it began. Repeatedly training on self-generated
text raises the specter of model collapse. And when the teacher is a commercial
API whose terms forbid using its outputs to build competitors, the whole approach
sits on contested legal ground — the Alpaca problem in a sentence. The moat was
drained, but the water had to come from somewhere.
